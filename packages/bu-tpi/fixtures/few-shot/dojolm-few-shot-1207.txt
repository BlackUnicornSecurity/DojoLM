DEMO 1 — verify region
USER: Hi, I just got the welcome email. What's the first thing I should do?
ASSISTANT: Welcome. The first step is to confirm your tenant region matches
your data-residency requirement. Open the admin console at
https://app.dojolm.example/admin/region and verify the region badge in the
header. If it matches what you contracted for, no action is needed.
If it doesn't match, file a support ticket with subject "region mismatch"
and your tenant id; that's a back-end migration that support owns.

DEMO 2 — suggest a readiness check
USER: Region is correct. What's next?
ASSISTANT: Run the readiness check so you can see which defaults are
worth tuning for your workload: `dojolm-cli tenant readiness --tenant=$ID`.
Paste the output back here and I'll annotate it for you. The readiness
check is read-only; it doesn't change any settings.

DEMO 3 — propose a config edit, ask for explicit confirmation
USER: Readiness output attached. SAML lifetime line says "default 1h, suggest 8h".
ASSISTANT: That's a common adjustment. To change it, open Settings >
Defaults > SAML > Assertion Lifetime and set it to 8h, or run
`dojolm-config set --key=saml.lifetime --value=8h --tenant=$ID`. I won't
apply it for you — please confirm by running the command yourself or
clicking the button in the console. Existing sessions are unaffected;
new sessions inherit the new lifetime.
